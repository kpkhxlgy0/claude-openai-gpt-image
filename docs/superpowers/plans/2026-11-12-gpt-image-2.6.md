# GPT Image 2.6 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add GPT Image 2.6 to the `gpt-image` plugin: the two 2.6 model IDs (new default `gpt-image-2.6-flare`), the `complexity` control, SVG output, animated GIF output, and markup-guided edits.

**Architecture:** Keep the existing layering (zod input schema → tool handler → `ImageProvider` → atomic publisher → strict output schema). New request fields are validated in `src/schemas.ts` before any paid call and passed through the existing hand-typed request bodies. Provider output for the two new formats is validated by two new hand-rolled inspectors (`src/images/gif.ts`, `src/images/svg.ts`) behind a new `inspectOutputImage` entry point, so `inspectImage` (used for edit *inputs*) keeps accepting PNG/JPEG/WebP only.

**Tech Stack:** TypeScript 7, zod 4.4.3, `openai` 6.49.0 (unchanged), Node built-in test runner via `tsx --test`, esbuild bundle to the tracked `dist/server.mjs`.

**Spec:** No separate spec document. The request was: "add base 2.6 support, change the default, implement SVG and GIF output, implement markup-guided edits". The API facts below were verified on 2026-11-12 against the official image-generation guide, the openai-node 7.51.0 `images.ts`, and the openai-openapi spec.

### Verified API facts

- Model IDs: `gpt-image-2.6-sunburst`, `gpt-image-2.6-flare`. Endpoints: `/v1/images/generations`, `/v1/images/edits`. Quality `xhigh`/`max` and transparent backgrounds work as on the 2.5 Sunburst/Flare models.
- `complexity`: top-level request field, `low | medium | high`; omitted means the model default (`high`). Documented for the 2.6 models.
- SVG: `output_format: "svg"` on generations only, `n = 1`, no `output_compression`. Response is `data[0].b64_json` = base64 of UTF-8 XML. Edits cannot output SVG; SVG is not a valid edit input.
- GIF: `output_format: "gif"` on generations or edits. `frame_count` integer 2–16 (default 9). `frame_duration_ms` integer 20–2000 (default 200). `size` is `auto` or `WIDTHxHEIGHT` in multiples of 16 and describes one frame; default `auto`. No custom `output_compression`, no masks. Response is `data[0].b64_json` = GIF bytes.
- Markup-guided edits: multipart field `markup` on `/v1/images/edits`, a transparent PNG with the same dimensions as the first input image after orientation. At most 16,777,216 pixels and 50 MB. Supported on GPT Image 2.5 and 2.6 Sunburst/Flare. Cannot be combined with `mask`.
- `openai` 6.49.0 serializes unknown body keys unchanged for both JSON and multipart requests (`createForm` iterates `Object.entries(body)`), so no SDK upgrade is needed.

## Global Constraints

- No new runtime or dev dependencies; `package.json`, `package-lock.json`, and the version `0.2.0` stay unchanged.
- Every rule that can be checked from the request alone throws `AppError("INVALID_INPUT", …)` in `src/schemas.ts` before any paid call. Rules that need file contents throw `INPUT_FILE_INVALID` in `src/tools/edit-image.ts`.
- `inspectImage` and edit inputs stay PNG/JPEG/WebP only. GIF and SVG are output-only formats.
- Provider output that fails inspection surfaces as `INVALID_PROVIDER_RESPONSE` with the existing message `Provider image payload failed validation`.
- Existing error message strings stay byte-identical unless a task says otherwise.
- TDD: write the failing test first, run it, implement, run it again. Run `npm run typecheck` and the task's test files before reporting.
- Do not commit, stage, or push. Do not run `npm run test:host` (it makes paid calls).
- `dist/server.mjs` is rebuilt only in Task 5.

## Review Focus

1. A provider SVG that hides active content behind entities, a namespace prefix, CDATA, or mixed case must be rejected, not published. (Task 2)
2. A GIF request that omits `size` must send `auto`, not the raster default `1024x1024`. (Task 3)
3. A `.gif` or `.svg` file passed in `image_paths` must still be rejected as an edit input. (Task 3)
4. A markup layer drawn for an EXIF-rotated JPEG has transposed dimensions relative to the stored JPEG; it must be accepted. (Task 4)
5. `frame_count` without GIF output, `complexity` on a non-2.6 model, and nonzero `output_compression` with GIF or SVG must fail before the provider is called. (Tasks 1 and 3)

### Task 2: GIF and SVG output inspectors

**Files:**
- Create: `src/images/gif.ts`, `src/images/svg.ts`, `src/images/inspect-output.ts`, `test/gif-inspection.test.ts`, `test/svg-inspection.test.ts`

**Interfaces:**
- Produces in `src/images/types.ts`:
  ```ts
  export type OutputImageFormat = ImageFormat | "gif" | "svg";
  export type OutputImageMimeType = ImageInfo["mimeType"] | "image/gif" | "image/svg+xml";
  export interface OutputImageInfo {
    format: OutputImageFormat;
    mimeType: OutputImageMimeType;
    width: number;
    height: number;
    hasAlpha: boolean;
    frameCount?: number; // GIF only
  }
  export const MAX_SVG_BYTES = 16 * 1024 * 1024;
  export const MAX_GIF_FRAMES = 256;
  ```
- Produces: `inspectGif(bytes: Uint8Array): OutputImageInfo`, `inspectSvg(bytes: Uint8Array): OutputImageInfo`, and `inspectOutputImage(bytes: Uint8Array, format: OutputImageFormat): Promise<OutputImageInfo>` (delegates `png`/`jpeg`/`webp` to `inspectImage(bytes, format)`).
- Produces fixtures: `makeGif(options?: { width?: number; height?: number; frames?: number; transparent?: boolean; version?: "87a" | "89a" }): Buffer` and `makeSvg(body?: string, rootAttributes?: string): Buffer`.
- All failures throw `AppError("INPUT_FILE_INVALID", "Invalid GIF: …")` or `"Invalid SVG: …"`.

**GIF rules (structural; LZW data is not decoded):** signature `GIF87a` or `GIF89a`; logical screen width/height through `assertImageDimensions`; optional global color table; then a block loop until the `0x3B` trailer, which must be the last byte. Extension blocks (`0x21`) are skipped sub-block by sub-block; a Graphic Control Extension (`0xF9`) must have block size 4 and sets `hasAlpha` when its transparency flag is set. Image descriptors (`0x2C`) must have nonzero width/height inside the logical screen, an LZW minimum code size of 2–8, and at least one data sub-block; each one counts as a frame. Truncation anywhere, an unknown block introducer, zero frames, or more than `MAX_GIF_FRAMES` frames is invalid.

**SVG rules:** reject more than `MAX_SVG_BYTES`; decode as UTF-8 with `fatal: true` (strip one BOM); reject C0 control characters other than tab, LF, CR. Tokenize in a single linear pass (no regex backtracking over the whole document):
- Allowed at top level: one leading `<?xml … ?>` declaration, comments, whitespace, exactly one root element named `svg` (no prefix). Any other processing instruction, `<!DOCTYPE`, `<!ENTITY`, or other `<!` construct outside comments and CDATA is invalid. CDATA is allowed only inside the root.
- Tags must be well formed and balanced; attribute values must be quoted; duplicate attributes on one element are invalid.
- Entity references are allowed only as `&lt; &gt; &amp; &quot; &apos;` or numeric references; attribute values are entity-decoded before the checks below.
- Namespace declarations (`xmlns`, `xmlns:*`) must equal the SVG namespace or the XLink namespace exactly.
- Denied element local names (prefix stripped, case-insensitive): `script`, `foreignObject`, `image`, `feImage`, `animate`, `animateMotion`, `animateTransform`, `set`, `discard`, `handler`, `listener`, `iframe`, `embed`, `object`, `audio`, `video`, `canvas`, `link`, `meta`, `base`.
- Denied attributes: any name starting with `on` (case-insensitive); `href`, `*:href`, and `src` whose trimmed value does not start with `#`.
- Every attribute value and every `style` element text (including CDATA) is checked after removing whitespace and control characters and lowercasing: it must not contain `javascript:`, `vbscript:`, `@import`, `expression(`, or a backslash inside `style` content or a `style` attribute; every `url(` must be followed (after an optional quote) by `#`.
- Dimensions: root `width`/`height` when both match a non-negative number with optional `px`; otherwise the third and fourth `viewBox` numbers; otherwise the CSS default 300×150. Round to the nearest integer, minimum 1; non-finite values are invalid. Do not apply `assertImageDimensions`.
- Result: `{ format: "svg", mimeType: "image/svg+xml", width, height, hasAlpha: true }`.

## Deviations made during execution

Review findings changed these points after the plan was written. The code and the user documentation are the authority where they differ from the task text above.

- **SVG elements:** the inspector uses an allow-list of static SVG element names instead of the deny-list in Task 2, and `title`, `desc`, and `metadata` may contain text only. A security review showed that the deny-list let script run when an accepted SVG was pasted inline into an HTML page.
- **SVG attributes:** values of unprefixed `aria-*` and `data-*` attributes and of `xlink:title` are not content-checked (they are prose); the `expression(` check was removed; `ping` and `xml:base` are rejected outright; a default-namespace declaration must name the SVG namespace; CSS `src(` and `image(` are rejected.
- **SVG DOCTYPE:** the two standard public SVG 1.0 and 1.1 DOCTYPE declarations are accepted; every other DOCTYPE is rejected.
- **SVG limits:** element nesting is limited to 512 levels.
- **GIF limits:** the sum of frame areas is limited to 16 × `MAX_IMAGE_PIXELS`.
- **Validator:** `scripts/validate-package.mjs` exempts the exact XML identifier literals the SVG inspector needs instead of approving the host `www.w3.org`.
- **Markup dimensions:** the transposed match is accepted only when the first image is a JPEG or WebP; a PNG first image must match exactly.
- **Result building:** the size comparison after publication never throws; a single-frame GIF is reported as `1 frame`.
- **Format mismatch message (after execution):** when provider bytes fail inspection and `detectOutputImageFormat` (`src/images/detect-format.ts`) recognizes a different output format by its signature (for SVG, the first element after the prolog must be the `<svg` root, within the first 1024 bytes), `INVALID_PROVIDER_RESPONSE` says `Provider returned <detected> output, but <requested> was requested`; every other inspection failure keeps `Provider image payload failed validation`.
- **Provider failure status (after execution):** `PROVIDER_FAILURE` messages include the HTTP status when it is an integer from 100 to 599, for example `The image provider request failed with HTTP 400`; no provider-authored text reaches the message.
